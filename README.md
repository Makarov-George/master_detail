# Master–Detail — система управления документами

Веб-приложение для создания, редактирования и удаления документов и связанных с ними строк спецификации.

## Технологии

- **Backend:** Java, Spring Boot, Spring Data JPA, Hibernate
- **Frontend:** Angular, TypeScript, HTML, CSS
- **База данных:** PostgreSQL
- **Сборка backend:** Maven
- **API:** REST

## Функциональность

- Создание, просмотр, редактирование и удаление документов (Master).
- Добавление, редактирование и удаление строк спецификации (Detail).
- Автоматический пересчёт общей суммы документа при изменении строк.
- Проверка уникальности номера документа.
- Логирование обнаруженных дубликатов в отдельную таблицу PostgreSQL.
- Сохранение записей об ошибках в независимой транзакции с использованием `Propagation.REQUIRES_NEW`.
- Проверка корректности вводимых данных.

## Структура базы данных

**master** — документы:
- `id` — идентификатор.
- `number` — уникальный номер.
- `date` — дата документа.
- `total` — общая сумма.
- `note` — примечание.

**detail** — строки спецификации:
- `id` — идентификатор.
- `name` — наименование.
- `total_det` — сумма строки.
- `document_id` — внешний ключ на документ.

**error_log** — журнал ошибок:
- `id` — идентификатор.
- `error_type` — тип ошибки.
- `error_message` — описание.
- `document_number` — номер документа.
- `created_at` — время возникновения.

## Запуск проекта

### Backend

1. Установить JDK, Maven и PostgreSQL.
2. Создать базу данных `master_detail_db` и необходимые таблицы.
3. Настроить подключение к PostgreSQL в `application.properties`.
4. Запустить Spring Boot приложение.

### Frontend

1. Установить Node.js и npm.
2. Перейти в каталог `frontend`.
3. Выполнить `npm install`.
4. Выполнить `ng serve` или `npx ng serve`.
5. Открыть `http://localhost:4200`.

## Особенности реализации

Для предотвращения дублирования номеров документов используется предварительная проверка в Spring Boot и ограничение `UNIQUE` в PostgreSQL.

При обнаружении дубликата приложением ошибка сохраняется в отдельной транзакции, поэтому запись журнала не зависит от отката основной операции.

## Тестирование

Вручную проверены CRUD-операции, пересчёт сумм, проверка уникальности и запись ошибок в PostgreSQL.
